Interface Triage Agent

A local AI agent that works an HL7 v2 interface error queue. It explains each rejected message in plain English, routes it to the team that owns the fix, and drafts the ticket. It runs entirely on a laptop, on synthetic patients.

How it works

  1. Build messages

    Synthea patients, encounters and labs become ADT and ORU messages.

  2. Inject faults

    Each queued message gets one known error; the answer key is kept aside.

  3. Validate

    Rule-based checks find every error with a rule ID and field path.

  4. Triage

    The local model explains, routes and drafts a ticket, looking up field definitions through a tool.

  5. Score

    Routing is graded against the answer key; explanations are hand-graded.

Code decides whether a message is broken; the model only explains why and who should fix it. Detection stays reproducible and auditable, and the model's mistakes are limited to wording and routing, which are measured here.

Where it missed

9 misroutes. Most common confusions: PID3_EMPTY → Interface team (4); PID7_FORMAT → Registration (2); OBX5_TYPE → Interface team (2); OBX11_EMPTY → Interface team (1).

  • OBX11_EMPTY went to Interface team instead of Lab system. The 'Observation result status' field is missing, which means the receiving system doesn't know if the result is final, preliminary, or corrected. This could lead to incorrect clinical decisions.
  • PID7_FORMAT went to Registration instead of Interface team. The date of birth (PID-7) is in the format '10/30/2006', which is not a valid HL7 date format. HL7 requires the date to be in 'YYYYMMDD' format, such as '20061030'. This will cause the receiving system to reject or…
  • OBX5_TYPE went to Interface team instead of Lab system. The value in OBX-5 is '<0.1', which is not a number, but the field OBX-2 is set to 'NM' (numeric). This mismatch can cause the system to misinterpret the result, leading to incorrect data processing or rejection.
  • PID7_FORMAT went to Registration instead of Interface team. The date of birth is not in the correct HL7 format (YYYYMMDD). This will cause the receiving system to reject or misinterpret the date, leading to potential errors in patient records or clinical workflows.
  • PID3_EMPTY went to Interface team instead of Registration. The patient's medical record number (MRN) is missing, which is critical for identifying the correct patient and linking results to their record.
  • PID3_EMPTY went to Interface team instead of Registration. The patient's medical record number (MRN) is missing, which is critical for identifying the correct patient in the system. This will prevent the lab results from being correctly associated with the patient.
  • OBX5_TYPE went to Interface team instead of Lab system. The value in OBX-5 is 'see comment,' which is not a number, but OBX-2 is set to NM (numeric). This breaks the requirement for the observation value to be numeric, which is necessary for proper data processing and…
  • PID3_EMPTY went to Interface team instead of Registration. The patient's medical record number (MRN) is missing, which is essential for correctly identifying the patient in the system. This can lead to incorrect results being associated with the wrong patient.

About the data

Every patient is synthetic, generated by Synthea. No real patient data, hospital messages or vendor documentation were used. The agent runs through Ollama on localhost, so nothing leaves the machine. This is a learning project, not clinical tooling; running locally does not by itself make a device approved for real patient data.
