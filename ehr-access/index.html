EHR Access Monitoring

Detecting insider snooping in hospital audit logs: who opened a patient's chart without a reason to. SQL rules check every chart access against care-team assignments, encounters and roles, then rank users into an investigation queue.

SQL (SQLite)PythonHIPAA audit controlsInsider threatEHR / Epic-style audit logsDetection tuning

All data is synthetic. "Riverside General Hospital", its staff and patients are fictional and generated by code in this repo. No real PHI, no real organization, no employer data.

Why this matters

Hospitals must record and regularly review who accesses patient records. The hard part isn't logging, it's review: tens of thousands of chart opens a month, almost all legitimate. A privacy analyst needs a short, ranked list of the people worth investigating, not a wall of alerts. This project builds that list and measures how good it is.

How it works

IngestAudit log, users, patients, encounters and care teams load into SQLite.
Relationship checkEach access is tested: care team, role-based need (lab, pharmacy, registration, billing), or justified emergency access.
Rules9 SQL rules flag patterns among accesses with no relationship.
Risk queueRule weights roll up into one score per user, ranked for review.

Results: baseline, then tuned

v1 used only the core clinical tables. Reviewing its false alerts showed they were legitimate work the rules couldn't see. v2 adds three context sources real hospitals already have (consult orders, approved work queues, staffing schedules) and two behavioral rules for the misuse v1 missed.

What's still hard

  • Curiosity hidden inside a real emergency. An ED nurse used break-the-glass on a coworker's live ED visit. The override looks justified, so v2 still misses it. Fix: always review break-the-glass on staff and VIP records, even when an emergency is active.
  • Rule R9 flags the whole pattern. It marks every open by the over-accessing team member, including routine ones, which accounts for most of v2's remaining false events. At user level the call is correct.
  • Float coverage with no assignment on record still looks like snooping. That is a data-quality gap to fix at the source, not with a looser rule.
  • Thresholds are tuned to this data. A real deployment would baseline each role and unit (peer groups) before setting limits.
