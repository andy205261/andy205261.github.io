What this project demonstrates

A Clinical Systems Analyst lives at the junction of three languages — clinical workflow, system configuration, and risk. These simulations were built around the judgment calls that define the role: knowing that a deferred message queue is patients' results, that resolution is not closure until the delayed-criticals review runs, that a routing fix must be paired with a sweep of everything already misrouted, and that severity is defined by clinical impact, not system metrics.

HL7 & INTEROPERABILITY

ORU/ADT/ORM message anatomy, placer–filler matching, sequence integrity, interface incident command, minimum-necessary feed design.

EPIC OPERATIONS

EMP/SER security model, SmartTools, order build layers, EPS printing, Data Courier discipline, SU/Nova/Sherlock upgrade rhythm.

DATA & REPORTING

Chronicles → Clarity → Caboodle → Slicer Dicer stack fluency, metric definition governance, tool-fit routing.

SAFETY & COMPLIANCE

BCMA five rights, alert-fatigue tuning by data, Cures Act release rules, break-the-glass, audit role separation, downtime readiness.

Why this exists: built as career preparation for the Clinical Systems Analyst → IAM → Healthcare Security Engineering path — the same method as the CySA+ interactive trainer: turn the target role's daily reality into a practice environment, then rehearse it until the safe path is reflex, not recall.
